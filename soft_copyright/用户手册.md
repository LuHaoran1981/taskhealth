# TaskHealth 用户手册

## 1. 软件概述

TaskHealth 是一款 Linux 用户态线程健康监控软件，填补 systemd（进程级）和 QNX HAM
（Linux 不可用）在线程层面健康监控的空白。

**软件架构：** 客户端-守护进程（Client-Daemon）架构，灵感来源于 QNX High Availability
Manager（HAM）。

- **守护进程 taskhealthd**：独立运行的监控进程，通过 Unix 域套接字（SOCK_SEQPACKET）
  接受多个业务进程的注册，统一执行线程心跳检测、死锁探测和告警输出
- **客户端库 libtaskhealth**：链接到业务进程，通过 IPC 协议向守护进程发送注册、
  心跳、注销等消息

**主要功能：**

| 功能 | 描述 |
|------|------|
| 线程意外退出检测 | 注册线程在未注销情况下退出时触发告警 |
| 死锁检测 | 心跳超时且线程阻塞在 futex 上时触发告警 |
| 等锁超时检测 | 线程等待 futex 超过设定阈值时触发告警 |

**运行环境：**
- Linux 3.x+ 内核，需 `/proc` 文件系统
- GCC（C11），GNU Make
- 无外部库依赖

## 2. 软件构成

### 2.1 守护进程（daemon/）

| 文件 | 说明 |
|------|------|
| `main.c` | 守护进程入口，CLI 参数解析，信号处理，daemonize |
| `server.c/h` | Unix 域套接字 epoll 服务端，消息分发 |
| `registry.c/h` | 线程注册表（固定大小数组，默认 4096 条目）|

| `alert.c/h` | 告警输出：syslog → stderr → 外部告警脚本 |

| `taskhealth_mutex.h` | 配套互斥锁头文件 |

## 3. 安装与构建

### 编译

```sh
make            # 编译静态库 libtaskhealth.a + 守护进程 taskhealthd
make all-full   # 静态库 + 共享库 + 守护进程 + 演示程序 + 单元测试
make check      # 编译并运行单元测试
make install    # 安装到 /usr/local
```

自定义安装路径：

```sh
make install prefix=/usr DESTDIR=/tmp/pkg
```

### 打包

```sh
make deb        # Debian / Ubuntu
make rpm        # Fedora / RHEL
```

## 4. 使用说明

### 4.1 启动守护进程

```sh
taskhealthd [OPTIONS]

选项：
  -s, --socket PATH    套接字路径（默认：/run/taskhealth.sock）
  -i, --interval MS    Watchdog 扫描间隔（ms，范围 100-60000，默认 1000）
  -m, --max-entries N   最大监控线程数（默认 4096）
  -d, --daemonize       以守护进程方式运行
  -a, --alert-script    告警脚本路径
  -v, --version         打印版本号
  -h, --help            打印帮助信息
```

示例：

```sh
# 前台运行，自定义套接字路径和扫描间隔
taskhealthd -s /tmp/taskhealth.sock -i 500 -m 1024

# 后台守护进程运行
taskhealthd -d -s /run/taskhealth.sock
```

### 4.2 初始化客户端

```c
#include "taskhealth.h"

struct taskhealth_config cfg = {0};
strncpy(cfg.socket_path, "/run/taskhealth.sock", sizeof(cfg.socket_path) - 1);

int rc = taskhealth_init(&cfg);
// 返回 0 表示成功
// cfg 为 NULL 时使用默认套接字路径 /run/taskhealth.sock
```

### 4.3 线程注册与心跳

```c
// 工作线程中注册
int rc = taskhealth_register("worker-1", 3000, 0);
//   name:           线程名称（NULL 或空串时自动从 /proc/self/comm 生成）
//   gap_ms:         心跳超时 (ms)，0=只检测退出，死锁+等锁不触发
//   lock_hold_ms:   等锁超时 (ms)，0=不检测等锁

// 工作循环中周期性更新心跳
while (running) {
    taskhealth_heartbeat();
    do_work();
}

// 正常退出前注销（不触发意外退出告警）
taskhealth_unregister();
```

### 4.4 参数组合规则

| gap_ms | lock_hold_ms | 检测能力 |
|--------|:---:|---------|
| 0 | 0 | 仅线程退出检测 |
| >0 | 0 | 退出 + 死锁 |
| 0 | >0 | 仅退出（lock_hold_ms 依赖 gap_ms）|
| >0 | >0 | 全部（退出 + 死锁 + 等锁超时）|

注意：等锁超时检测（lock_hold_ms）依赖心跳超时（gap_ms > 0），因为锁检测仅在
/proc 探针阶段（心跳超时后）执行。

### 4.5 告警输出

守护进程输出以下三类告警到 stderr / syslog / 外部脚本：

```
[taskhealthd] UNEXPECTED_EXIT thread 'name' pid=PID tid=TID unexpectedly exited
[taskhealthd] DEADLOCK thread 'name' pid=PID tid=TID blocked on futex wchan=FUTEX futex=ADDR module=MODULE+OFFSET
[taskhealthd] LOCK_WAIT thread 'name' pid=PID tid=TID lock-wait timeout waited=MSms futex=ADDR module=MODULE+OFFSET
```

使用外部告警脚本时，守护进程设置环境变量：
- `TASKHEALTH_TYPE`（EXIT / DEADLOCK / LOCK_WAIT）
- `TASKHEALTH_NAME`、`TASKHEALTH_PID`、`TASKHEALTH_TID`
- `TASKHEALTH_WAIT_MS`、`TASKHEALTH_MODULE`、`TASKHEALTH_FUTEX`

### 4.6 关闭

```c
taskhealth_shutdown();  // 发送 MSG_SHUTDOWN，关闭套接字连接
```

## 5. 检测原理

Watchdog 线程周期性（默认 1s）扫描所有注册线程：

- **退出检测**（始终生效）：`syscall(SYS_tgkill, pid, tid, 0)`，
  返回 ESRCH 即线程已退出

- **死锁检测**（gap_ms > 0）：
  1. 心跳超时（now - last_heartbeat > gap_ms）
  2. 读 `/proc/<pid>/task/<tid>/status` 解析线程状态（S 或 D）
  3. 读 `/proc/<pid>/task/<tid>/wchan`（阻塞在 futex）
  4. 读 `/proc/<pid>/task/<tid>/syscall` 获取 futex 地址
  5. 读 `/proc/<pid>/maps` 解析 futex 地址所属模块

- **等锁超时**（gap_ms > 0 且 lock_hold_ms > 0）：
  线程阻塞在 futex 期间累计等待时间，超过 lock_hold_ms 时告警。
  线程恢复时自动归零累计时间。

**与进程内库方案的关键区别：**
- /proc 路径使用 `<pid>` 而非 `self`（跨进程探测）
- 使用 `tgkill(pid, tid, 0)` 而非 `pthread_kill(tid, 0)`（跨进程信号）
- 注册表在守护进程内（跨进程共享）

## 6. IPC 协议

客户端与守护进程通过 Unix 域套接字（SOCK_SEQPACKET）通信，
每条消息由 8 字节定长帧头 + 可变长消息体组成：

| 消息类型 | 方向 | 说明 |
|----------|------|------|
| MSG_REGISTER | 客户端→守护进程 | 注册线程（pid, tid, name, gap_ms, lock_hold_ms）|
| MSG_UNREGISTER | 客户端→守护进程 | 注销线程（pid, tid）|
| MSG_HEARTBEAT | 客户端→守护进程 | 心跳更新（pid, tid）|
| MSG_SHUTDOWN | 客户端→守护进程 | 通知进程退出，清理该 PID 所有注册 |
| MSG_RESPONSE | 守护进程→客户端 | 注册响应（status: OK / TABLE_FULL / ALREADY_REG / INVALID_ARG）|

## 7. 错误码

| 返回值 | 含义 |
|--------|------|
| 0 | 成功 |
| -1 | 未初始化（守护进程不可达或连接断开）|
| -2 | 已初始化（重复调用 init）|
| -3 | 线程表已满 |
| -4 | 当前线程已注册 |
| -5 | 当前线程未注册 |
| -6 | 无效参数 |
